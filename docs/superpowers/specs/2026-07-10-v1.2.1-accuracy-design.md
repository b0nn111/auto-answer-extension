# 1.2.1 Accuracy Update Design

## Goal

Improve answer correctness and transparency without changing the extension's local-first storage model or adding new external services.

## Scope

- Detect whether a choice question uses checkboxes and mark it as multiple-choice.
- Normalize single- and multiple-choice answers through one shared library.
- Carry normalized `optionLetters` with every matched choice candidate.
- Highlight every selected option for multiple-choice answers while rendering one answer badge.
- Boost candidates when independent sources agree on the same normalized answer.
- Warn when available sources disagree.
- Record aggregate recent latency and failure information for cache, material retrieval, public search, local AI, and AI API calls.
- Limit concurrent question processing to four workers to reduce rate-limit and timeout failures.
- Show recent source timing or failure state in popup diagnostics.
- Add deterministic Node-based regression tests.
- Bump extension and package version to 1.2.1.

## Answer Contract

For choice questions, a candidate may include:

- `answer`: normalized display text, such as `B. Paris` or `A. One；C. Three`.
- `rawAnswer`: original source output.
- `optionLetters`: normalized uppercase option letters in page order.
- `confidence`: final score after source, option-match, and agreement adjustments.
- `consensusCount`: number of distinct sources that produced the same normalized answer.
- `warning`: mismatch or cross-source conflict message when applicable.

Non-choice answers keep their existing text contract.

## Ranking

Existing source and option-match scoring remains the base. Candidates are grouped by normalized option set for choice questions and normalized answer text for other questions. Agreement from each additional distinct source adds a bounded score boost. Source outputs remain individually visible so users can inspect which services agreed.

If more than one normalized answer group remains, the result exposes a conflict warning. Agreement is treated as stronger evidence, not proof of correctness.

## Diagnostics

Only aggregate runtime metadata is retained in service-worker memory: request count, success/failure count, latest latency, and a shortened latest error. Question text and answers are not stored in diagnostics. Metrics reset naturally when the MV3 service worker restarts.

## Error Handling

- Unparseable choice answers remain visible as text and are not attached to an arbitrary option.
- A partially invalid multiple-choice letter set is treated as unmatched.
- Source failures do not prevent other enabled sources from returning candidates.
- Diagnostic errors are shortened before reaching the popup.

## Testing

Regression tests cover single-choice normalization, common multiple-choice formats, invalid letters, exact-cache behavior, source consensus, conflict warnings, bounded concurrency, HTML escaping, number-input fill answers, and disabling the extension. Static JavaScript, manifest, package-content, and Git diff checks remain release gates.

## Out Of Scope

- PDF or Word material parsing.
- Persisted per-provider accuracy learned from user feedback.
- New quiz-platform adapters.
- Automatic question archiving.
