# 1.3.0 本地文档与资料引用设计

## 目标

在不上传原文件、不引入云端转换服务的前提下，让资料库支持可提取文字的 PDF 和 DOCX，并把命中的资料位置展示给用户核对。现有纯文本格式、文件夹和单文件启停逻辑继续保留。

## 已确认的产品边界

- PDF、DOCX 和现有纯文本格式全部在浏览器扩展本地解析。
- PDF 使用随扩展打包的 PDF.js；DOCX 使用随扩展打包的 Mammoth，并在本地转换为结构化文本/Markdown。
- 第三方库不得从 CDN 或其他远程地址加载，发布包包含对应许可证和版权说明。
- 不保存 PDF 或 DOCX 原文件，只保存提取文本、Markdown、检索片段和引用元数据。
- PDF 引用保留页码；DOCX 引用优先保留标题路径，否则使用段落序号。
- 不支持扫描版 PDF OCR、加密 PDF、旧版 `.doc` 和 PPT/PPTX。
- 单个导入文件上限为 50 MB。
- 资料本身不生成答案。未配置 AI 时只显示相关资料片段，不将片段标成答案。
- 账号、端到端加密同步、内置离线模型和平台托管 AI 均不属于 1.3.0。

## 用户流程

1. 用户在设置页选择已有资料文件夹，再选择一个或多个文件。
2. 设置页按顺序处理文件，并为每个文件显示“等待中、解析中、建立索引、完成或失败”。
3. 解析器根据文件类型生成统一文档结构，包括正文块和位置元数据。
4. 文档切片完成后直接写入扩展同源 IndexedDB；解析期间不会替换现有文件。
5. 同一文件夹内存在同名文件时，用户确认后执行替换。只有新内容完整写入成功，旧内容才会删除。
6. 答题时只检索已启用文件夹中的已启用文件。
7. 有 AI 答案时，答案下方显示资料来源；没有 AI 答案但资料命中时，只显示“找到相关资料”及片段。

## 组件设计

### 本地文档解析器

新增仅由设置页加载的 `MaterialParser`，按扩展名和 MIME 类型分派：

- PDF：PDF.js worker 逐页读取文字项，按阅读顺序整理空格和换行。每页形成独立块并保留 1 开始的页码。
- DOCX：Mammoth 将文档转换为本地 HTML，再通过随扩展打包的 Turndown 转成 Markdown，保留标题、段落、列表和表格文字。图片不上传，也不做 OCR。
- 文本文件：沿用 UTF-8 文本读取，但输出同一套统一文档结构。

解析器返回文档级元数据和有序内容块，不直接操作题目、AI 或页面标注。解析发生在设置页，避免把大文本通过 `chrome.runtime.sendMessage` 传给可能休眠的 MV3 service worker。

### 资料数据库

`AutoAnswerMaterialsDB` 升级到版本 2。现有三个 object store 保留，旧记录在升级后仍可读取。

版本 1 的文件记录缺少 `format`、`parserVersion` 和 `status` 时，读取层分别按 `text`、`1` 和 `ready` 处理；旧片段缺少位置字段时按普通文本片段显示。数据库升级不强制重写旧资料，也不要求用户重新导入。

文件记录新增：

- `format`：`pdf`、`docx` 或 `text`。
- `parserVersion`：用于以后判断是否需要重新索引。
- `pageCount`、`textLength` 和 `chunkCount`。
- `status`：持久化记录只允许 `ready`；解析中的临时状态只存在设置页内存中。

片段记录新增：

- `locatorType`：`page`、`heading` 或 `paragraph`。
- `pageNumber`：PDF 页码，没有时为空。
- `headingPath`：DOCX 标题路径，没有时为空数组。
- `paragraphStart` 和 `paragraphEnd`：没有稳定页码时用于定位。
- `markdown`：供引用展开和后续同步使用的规范化文本。

现有 `text` 字段继续保存用于检索的纯文本；`markdown` 保存展示与后续同步所需的结构化版本。检索层不直接解析 Markdown 标记。

切片优先在标题、段落或页边界处分割，目标长度约 900 字符并保留约 120 字符重叠。单个长段落才回退到固定长度分割。文件及全部片段在一个事务中写入；替换失败时保留旧文件。

### 检索与 AI 上下文

1.3.0 继续使用现有本地词法检索，不加入嵌入模型。检索结果在现有字段之外返回页码、标题路径和段落范围。

发送给本地 AI 或用户配置的 AI API 时，每个片段前包含稳定来源标签，例如：

```text
[微积分 / 第3周讲义.pdf / 第12页]
```

检索最多返回五个片段，现有文件夹与文件启停规则不变。删除或禁用文件后，对应片段立即停止参与检索。

### 页面引用展示

AI 候选答案保留其实际提供者，例如“本地 AI”或“AI API”，资料引用作为独立证据显示，不伪装成新的答案来源。

引用摘要格式：

```text
微积分 / 第3周讲义.pdf / 第12页
线性代数 / 矩阵复习.docx / 特征值 > 对角化
```

用户点击来源后展开命中的原文片段。所有文件名、标题和片段都经过 HTML 转义。若多个候选答案使用相同片段，界面可重复显示引用，但数据库不复制片段。

当没有任何 AI 或题库答案、但资料检索命中时，返回 `referenceOnly` 结果。页面显示“找到相关资料”及引用片段，不显示正确标记、置信度或选项高亮。

## 错误处理

- 超过 50 MB：导入前拒绝并显示文件大小限制。
- 加密 PDF：提示需要先移除密码，不尝试上传或绕过加密。
- 扫描版或图片版 PDF：没有提取到足够文字时提示“未检测到可提取文字，1.3.0 暂不支持 OCR”。
- 损坏 PDF/DOCX：显示该文件解析失败，同批其他文件继续处理。
- DOCX 中只有图片：按无可提取文字处理。
- 多栏、复杂表格或文字定位异常的 PDF：尽量按 PDF.js 返回顺序提取，并提示排版可能被简化；1.3.0 不承诺还原原版视觉布局。
- 存储空间不足：捕获 IndexedDB 配额错误，提示用户删除资料；替换操作保留旧版本。
- 同名文件：未经确认不覆盖；确认后仍采用先写新版本、成功后删除旧版本的顺序。
- 设置页关闭：未提交到 IndexedDB 的临时解析结果自然丢弃，数据库中不会留下 `processing` 半成品。

## 隐私与安全

- 文件解析、Markdown 转换、切片和索引全部在扩展页面内完成。
- 不添加文档转换、遥测或分析网络请求。
- 原文件 Blob、ArrayBuffer 和 DOCX 中的图片不写入 IndexedDB。
- 第三方解析库固定版本并随发布包分发，同时保留许可证文件。
- 解析得到的 HTML 从不直接插入页面；Markdown、文件名和引用片段在展示前统一转义。
- 只有用户已经启用云端 AI API 时，命中的文本片段才会按现有隐私规则发送到该 API。

## 测试与发布门槛

- 用真实的小型 PDF fixture 验证多页提取、页码和跨页切片。
- 用真实的小型 DOCX fixture 验证标题、列表、表格文字和段落定位。
- 验证扫描版空文本、加密或损坏文件、超大文件和不支持格式的错误分类。
- 验证数据库从版本 1 升级到版本 2 后，旧纯文本资料仍可检索。
- 验证同名替换成功、替换失败回滚、删除和启停过滤。
- 验证检索结果带引用字段，AI 提示词包含来源位置。
- 验证 `referenceOnly` 不显示正确标记、置信度或选项高亮。
- 验证引用中的恶意文件名和文档文本不会造成 HTML 注入。
- 验证发布包不引用 CDN，不包含导入的原始测试资料之外的用户文件，并包含第三方许可证。
- 运行现有 `scripts/test-extension.js` 回归测试并增加解析器、数据库迁移和引用展示测试。
- 在桌面和移动宽度测试 Moodle 页面，确保长引用可换行、展开区域无横向溢出。
